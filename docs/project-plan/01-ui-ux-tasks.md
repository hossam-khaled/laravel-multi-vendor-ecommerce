# مهام مصمم UI/UX — سوق متعدد التجار

> **مبدأ عام:** التصميم يسبق التنفيذ بسبرنت واحد على الأقل. تصاميم كل مرحلة يجب أن تكون معتمدة قبل أن يبدأ Frontend تنفيذها.
>
> **الأداة:** Figma — ملف مشترك مع الفريق، ومكتبة مكونات (Design System) تُبنى من البداية وتُستخدم في كل الشاشات.
>
> **قيود إلزامية في كل تصميم:** عربي RTL أولاً + نسخة إنجليزية LTR، وتصميم Mobile-First (نسخة جوال لكل شاشة أساسية)، والالتزام بألوان وخطوط الهوية المعتمدة.

## المخرجات العامة المطلوبة (Deliverables)

1. **Design System / مكتبة مكونات:** ألوان، خطوط (خط عربي + إنجليزي)، أزرار، حقول إدخال، بطاقات، جداول، تنبيهات، Modals، Badges، حالات فارغة (Empty States)، حالات تحميل.
2. **Wireframes** منخفضة الدقة لكل تدفق قبل التصميم النهائي.
3. **تصاميم نهائية High-Fidelity** لكل شاشة (جوال + ديسكتوب).
4. **Prototype تفاعلي** للتدفقات الحرجة (الشراء، تسجيل التاجر، سحب الأرباح).
5. **ملف تسليم للمطورين:** مسافات، أحجام، Tokens، وسلوك المكونات (hover/focus/error).

---

## المرحلة 0 — التأسيس (بالتوازي مع سبرنت 0)

- [ ] جلسة فهم المنتج مع مدير المشروع: الجمهور، المنافسون (نون، أمازون سعودية، سلة، زد)، نقاط التميز.
- [ ] تحليل 3–4 منصات منافسة (تدفق الشراء، صفحة المنتج متعدد الخيارات، لوحة التاجر).
- [ ] بناء الهوية البصرية للمنصة (أو استلامها إن وجدت) وتحويلها إلى Design Tokens.
- [ ] إنشاء ملف Figma وهيكلته (صفحة لكل مرحلة) + بدء مكتبة المكونات.
- [ ] تحديد الخط العربي (مثل IBM Plex Sans Arabic / Tajawal / Cairo) واختباره في RTL.

## المرحلة 1 — الحسابات والصلاحيات (يدعم M1)

- [ ] تدفقات التسجيل والدخول: عميل، وتاجر (نموذج طلب انضمام + شاشة "طلبك قيد المراجعة").
- [ ] شاشات استعادة كلمة المرور وتأكيد البريد (تحسين شاشات Breeze الحالية).
- [ ] هيكل لوحة تحكم الأدمن: القائمة الجانبية، الهيدر، مبدّل اللغة، صفحة رئيسية بمؤشرات.
- [ ] هيكل لوحة تحكم التاجر (مختلفة عن الأدمن: أبسط وأكثر تركيزاً على البيع).
- [ ] شاشات إدارة المستخدمين والأدوار والصلاحيات للأدمن (جدول مستخدمين، نموذج دور مع مصفوفة صلاحيات).
- [ ] شاشات موافقة الأدمن على طلبات التجار الجدد.
- [ ] صفحة إعدادات المتجر للتاجر (شعار، غلاف، وصف، بيانات التواصل).

## المرحلة 2 — الكتالوج والمتجر العام (يدعم M2)

**لوحة التاجر:**
- [ ] شاشة إضافة/تعديل منتج — **أهم شاشة في لوحة التاجر وأكثرها تعقيداً:**
  - منتج بسيط / منتج بخيارات (مقاس/لون…) مع مولّد Variants.
  - نوع البيع: قطعة / جملة / مختلط (أسعار وحدود كميات لكل نوع).
  - منتج متعدد الأجزاء (Bundle).
  - صور متعددة مع سحب وإفلات، وحقول SEO.
- [ ] شاشة إدارة المخزون: كميات لكل Variant، حدود التنبيه (أدنى/أقصى)، سجل حركات، تعديل يدوي بسبب.
- [ ] تصميم تنبيهات انخفاض المخزون (داخل اللوحة + بريد).

**المتجر العام (Storefront):**
- [ ] الصفحة الرئيسية: هيدر (بحث، سلة، حساب، لغة)، بنرات، أقسام مميزة، منتجات مميزة، تجار مميزين، بادجات، فوتر.
- [ ] صفحة القسم: فلاتر (سعر، تاجر، خيارات)، ترتيب، ترقيم صفحات، وموضع بنرات القسم.
- [ ] صفحة المنتج: معرض صور، اختيار الخيارات (لون/مقاس) بتحديث السعر والمخزون، أسعار الجملة، بطاقة التاجر، التقييمات (Placeholder)، منتجات مشابهة.
- [ ] صفحة المتجر/التاجر العامة: غلاف، تقييم، منتجات التاجر.
- [ ] نتائج البحث + حالة "لا نتائج".

## المرحلة 3 — الشراء والدفع (يدعم M3)

- [ ] السلة: صفحة كاملة + Mini-cart منسدلة، **مع تجميع المنتجات حسب التاجر** (تمهيد بصري لتقسيم الطلب)، وسلوك تعديل الكميات وحدود الجملة.
- [ ] قائمة الأمنيات.
- [ ] تدفق Checkout كامل (Prototype تفاعلي إلزامي): العنوان ← الشحن لكل تاجر ← الدفع ← المراجعة ← التأكيد.
- [ ] شاشة اختيار طريقة الدفع: بطاقة / مدى / Apple Pay / تابي / تمارا / عند الاستلام — بأيقونات المزودين الرسمية.
- [ ] صفحات نجاح/فشل الدفع.
- [ ] حساب العميل: طلباتي (مع عرض الطلب المقسّم بوضوح: طلب رئيسي وتحته شحنة لكل تاجر)، تفاصيل الطلب، تتبع الحالة، العناوين، الملف الشخصي.
- [ ] لوحة التاجر: قائمة الطلبات (sub-orders الخاصة به فقط)، تفاصيل الطلب، تغيير الحالة، بيانات الشحن.
- [ ] لوحة الأدمن: كل الطلبات والـ sub-orders، وشاشة إعدادات الشحن والضرائب.

## المرحلة 4 — المالية (يدعم M4)

- [ ] لوحة التاجر المالية: ملخص المحفظة (رصيد معلّق / متاح / إجمالي المبيعات / عمولات مخصومة)، كشف حركات.
- [ ] تدفق طلب سحب الأرباح للتاجر + شاشة إدارة طلبات السحب للأدمن (موافقة/رفض).
- [ ] شاشات إعدادات العمولات للأدمن: عمولة افتراضية، عمولة لكل قسم، عمولة لكل تاجر.
- [ ] قوالب الفواتير (PDF قابل للطباعة، عربي/إنجليزي): فاتورة العميل الضريبية، فاتورة عمولة المنصة للتاجر.
- [ ] تدفق المرتجعات للعميل (طلب إرجاع من تفاصيل الطلب، سبب، صور، تتبع الحالة) + شاشات معالجة المرتجع للتاجر والأدمن.

## المرحلة 5 — النمو (يدعم M5)

- [ ] شاشات الكوبونات والعروض (إنشاء وإدارة للأدمن وللتاجر) + حقل الكوبون في السلة/الدفع.
- [ ] التقييمات: نموذج تقييم بعد الاستلام، عرض التقييمات في صفحة المنتج والتاجر، شاشة إشراف الأدمن.
- [ ] مركز الإشعارات (جرس + قائمة) في اللوحات والمتجر + قوالب البريد الإلكتروني (طلب جديد، شحن، تسليم…).
- [ ] لوحة التحليلات: تصميم بطاقات المؤشرات والرسوم البيانية (مبيعات، أفضل منتجات/تجار) للأدمن وللتاجر.
- [ ] شاشات إدارة البنرات والبادجات للأدمن.
- [ ] المدونة: قائمة المقالات، صفحة المقال، إدارة المقالات في لوحة الأدمن.

## المرحلة 6 — الإطلاق (يدعم M6)

- [ ] مراجعة UX شاملة على Staging (Usability Review) وتسجيل الملاحظات كمهام.
- [ ] مراجعة المطابقة النهائية بين التصميم والتنفيذ (Design QA) شاشة بشاشة.
- [ ] صفحات ثابتة: من نحن، الشروط والأحكام، سياسة الاسترجاع، الخصوصية، تواصل معنا، 404/500.
- [ ] أصول الإطلاق: أيقونات التطبيق/الفافيكون، صور المشاركة (OG images)، وبنرات الإطلاق.

---

## معايير قبول عمل المصمم

- كل شاشة لها نسختان: جوال + ديسكتوب، وعربي RTL (الإنجليزية يكفي فيها Mirror مع مراجعة النصوص).
- كل مكوّن مبني من مكتبة المكونات وليس عنصراً منفصلاً.
- كل تدفق حرج له Prototype قابل للنقر قبل التنفيذ.
- تسليم التصاميم يتم بإشعار في لوحة المهام مع رابط Figma للصفحة المحددة، ويُعتبر مُسلّماً بعد اعتماد مدير المشروع.
- التجاوب مع أسئلة المطورين على التصاميم خلال يوم عمل كحد أقصى.
