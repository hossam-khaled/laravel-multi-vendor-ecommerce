# مهام مطور Frontend — سوق متعدد التجار

> **التقنيات المعتمدة (الموجودة في المشروع):** Blade + Tailwind CSS + Alpine.js + Vite. لا يُدخل إطار جديد (Vue/React) إلا بقرار من مدير المشروع في سبرنت 0.
>
> **قواعد عامة إلزامية:**
> - **RTL أولاً:** كل شاشة تُبنى وتُختبر بالعربية (RTL) ثم تُتحقق بالإنجليزية (LTR). استخدم خصائص Tailwind المنطقية (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`) بدل left/right.
> - **Mobile-First:** كل شاشة تُختبر على الجوال قبل اعتبارها منجزة.
> - كل النصوص عبر ملفات الترجمة (`__()` / `@lang`) — ممنوع نص ثابت (Hardcoded) في القوالب.
> - الالتزام بتصاميم Figma المعتمدة؛ أي غموض يُسأل عنه المصمم قبل الاجتهاد.
> - مكونات Blade (`resources/views/components`) قابلة لإعادة الاستخدام لكل عنصر متكرر — المشروع فيه مكونات نماذج جاهزة يُبنى عليها.

## المرحلة 0 — التأسيس (سبرنت 0)

- [ ] مراجعة الواجهات الحالية (لوحة التحكم، مكونات النماذج، layouts) وتوثيق ما يُعاد استخدامه.
- [ ] إعداد أساس RTL/LTR: اتجاه `<html dir>` حسب اللغة، تحميل الخط العربي المعتمد، وضبط Tailwind للخصائص المنطقية.
- [ ] بناء نظام مكونات أساسي مطابق لـ Design System من Figma: أزرار، حقول، Select، بطاقات، جداول، Badge، Alert، Modal، Tabs، Pagination، Empty State، Skeleton loading.
- [ ] إعداد مبدّل اللغة (ar/en) في الهيدر واللوحات.

## المرحلة 1 — الحسابات واللوحات (M1)

- [ ] إعادة بناء شاشات المصادقة (دخول/تسجيل/استعادة) حسب التصميم الجديد، بنسختي العميل والتاجر.
- [ ] نموذج طلب انضمام التاجر (خطوات متعددة) + شاشة "طلبك قيد المراجعة".
- [ ] قالب لوحة الأدمن: Sidebar قابلة للطي (تعمل RTL)، هيدر، Breadcrumbs، قائمة مستخدم، جرس إشعارات (Placeholder).
- [ ] قالب لوحة التاجر (منفصل وأبسط).
- [ ] شاشات إدارة المستخدمين والأدوار: جدول مع بحث وفلترة، ونموذج دور بمصفوفة صلاحيات (Checkboxes مجمعة).
- [ ] شاشة موافقات التجار للأدمن.
- [ ] صفحة إعدادات المتجر للتاجر مع رفع الشعار/الغلاف (معاينة قبل الرفع).
- [ ] تعريب كامل الشاشات المنجزة سابقاً (الأقسام/المتاجر/المنتجات الحالية) ونقلها للتصميم الجديد.

## المرحلة 2 — الكتالوج والمتجر العام (M2)

**لوحة التاجر:**
- [ ] شاشة إضافة/تعديل المنتج — **أثقل مهمة تفاعلية في المشروع (Alpine.js):**
  - تبديل نوع المنتج (بسيط/خيارات/Bundle) بإظهار الحقول المناسبة.
  - مولّد Variants ديناميكي: اختيار الخصائص (لون/مقاس) ← توليد جدول Variants قابل للتحرير (SKU/سعر/سعر جملة/كمية) — مع الحفاظ على القيم المدخلة عند إعادة التوليد.
  - نوع البيع (قطعة/جملة/مختلط) بحقوله الشرطية.
  - رفع صور متعددة بسحب وإفلات، ترتيب، وحذف، مع معاينة.
- [ ] شاشة المخزون: جدول Variants بكميات، تعديل يدوي عبر Modal بسبب، عرض سجل الحركات، ومؤشرات لونية للحدود.

**المتجر العام (Storefront) — يُبنى Layout مستقل عن اللوحات:**
- [ ] Layout المتجر: هيدر (شعار، بحث، لغة، حساب، أمنيات، سلة بعدّاد)، قائمة أقسام، فوتر.
- [ ] الصفحة الرئيسية: سلايدر بنرات، شبكات أقسام ومنتجات وتجار، بادجات — بأداء جيد (Lazy loading للصور).
- [ ] صفحة القسم: فلاتر جانبية (Drawer على الجوال)، ترتيب، ترقيم، بطاقة منتج موحدة (صورة، بادج، سعر/سعر مخفض، تقييم، زر سلة/أمنيات).
- [ ] صفحة المنتج: معرض صور مع Thumbnails وZoom، اختيار الخيارات بتحديث السعر/الصورة/المخزون فورياً (Alpine)، جدول أسعار الجملة، كمية مع حدود، بطاقة تاجر، تبويبات (وصف/تقييمات)، منتجات مشابهة.
- [ ] صفحة المتجر العامة وصفحة نتائج البحث.

## المرحلة 3 — الشراء والدفع (M3)

- [ ] السلة: صفحة كاملة **مجمّعة حسب التاجر**، تعديل كميات مع تحقق حدود الجملة والمخزون (تحديث دون إعادة تحميل)، وMini-cart في الهيدر.
- [ ] قائمة الأمنيات مع نقل للسلة.
- [ ] تدفق Checkout متعدد الخطوات: عناوين (إضافة/اختيار)، شحن لكل تاجر، طرق الدفع، مراجعة نهائية بتفصيل (منتجات لكل تاجر + شحن + ضريبة + خصم) — مع حفظ التقدم بين الخطوات.
- [ ] تكامل واجهة الدفع مع المزود (عناصر البطاقة المضمّنة/إعادة التوجيه حسب المزود)، وزر Apple Pay، وواجهات تابي/تمارا، وحالات نجاح/فشل واضحة.
- [ ] حساب العميل: طلباتي (بطاقة طلب تُظهر الشحنات المتعددة)، تفاصيل الطلب مع Timeline للحالة، العناوين، الملف الشخصي، المرتجعات.
- [ ] لوحة التاجر: جدول الطلبات بفلترة حسب الحالة، تفاصيل sub-order، تغيير الحالة، إدخال رقم تتبع، طباعة بوليصة/فاتورة.
- [ ] لوحة الأدمن: شاشات كل الطلبات، وإعدادات الشحن والضريبة.

## المرحلة 4 — المالية (M4)

- [ ] لوحة التاجر المالية: بطاقات الأرصدة، جدول حركات المحفظة بفلترة، ونموذج طلب سحب.
- [ ] شاشات الأدمن: طلبات السحب (موافقة/رفض مع سبب)، إعدادات العمولات (افتراضية/قسم/تاجر)، أرشيف الفواتير.
- [ ] عرض الفواتير: صفحة HTML للفاتورة + زر تحميل PDF (القالب من الـ Backend، التنسيق مطابق للتصميم).
- [ ] تدفق المرتجعات: نموذج طلب إرجاع (اختيار المنتجات، سبب، رفع صور)، تتبع حالة الطلب، وشاشات المعالجة للتاجر والأدمن.

## المرحلة 5 — النمو (M5)

- [ ] شاشات الكوبونات (أدمن + تاجر) + حقل الكوبون في السلة/Checkout مع رسائل نجاح/خطأ فورية.
- [ ] التقييمات: نموذج تقييم بنجوم من صفحة الطلب المُسلّم، عرض التقييمات مع توزيعها في صفحة المنتج، وشاشة الإشراف للأدمن.
- [ ] مركز الإشعارات: جرس بعدّاد + قائمة منسدلة + صفحة كل الإشعارات (للعميل والتاجر والأدمن) + تعليم كمقروء.
- [ ] لوحة التحليلات: بطاقات مؤشرات ورسوم بيانية (Chart.js أو ApexCharts) بدعم RTL، مع فلترة بالفترة الزمنية.
- [ ] إدارة البنرات للأدمن (رفع صورة لكل لغة، جدولة، ترتيب بسحب وإفلات) وعرضها في المتجر.
- [ ] المدونة: قائمة المقالات وصفحة المقال في المتجر + محرر المقالات في لوحة الأدمن (محرر نصي غني).

## المرحلة 6 — التقوية والإطلاق (M6)

- [ ] الأداء: تحسين الصور (lazy/srcset/WebP)، تقليص حزم JS/CSS عبر Vite، وفحص Lighthouse (هدف: 85+ أداء للجوال في الصفحات الرئيسية).
- [ ] فحص متصفحات وأجهزة: Chrome/Safari/Firefox + iOS Safari وAndroid Chrome (خاصة Apple Pay وحقول الدفع).
- [ ] Accessibility أساسية: تباين ألوان، تنقل بلوحة المفاتيح في النماذج، نصوص بديلة للصور.
- [ ] الصفحات الثابتة وصفحات الأخطاء (404/500/503) حسب التصميم.
- [ ] جولة Design QA مع المصمم وإغلاق ملاحظات المطابقة.

## معايير قبول عمل مطور الـ Frontend

- كل شاشة: تطابق Figma، تعمل RTL/LTR، متجاوبة (جوال/تابلت/ديسكتوب)، ونصوصها من ملفات الترجمة.
- التفاعلات الحرجة (Variants، السلة، Checkout) تعمل دون أخطاء Console ودون إعادة تحميل غير ضرورية.
- كل PR يتضمن لقطات شاشة (جوال + ديسكتوب، عربي) لتسهيل المراجعة.
- المكونات المشتركة تُبنى مرة واحدة في `components/` وتُعاد تسميتها/توثيقها بوضوح.
